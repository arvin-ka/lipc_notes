## 1️⃣ تعیین سطح دسترسی پیش‌فرض کاربران (UMASK)

وقتی یک کاربر فایل یا دایرکتوری جدیدی می‌سازد، سیستم‌عامل به‌صورت خودکار مجوزهای اولیه (Default Permissions) را روی آن قرار می‌دهد. تعیین این مجوزهای اولیه توسط مفهومی به نام **`umask` (User Mask)** انجام می‌شود.

### 🔹 مقادیر پایه قبل از ماسک (Base Permissions):
* **حداکثر دسترسی پایه برای فایل‌ها:** `666` (`rw-rw-rw-`) — *فایل‌ها به‌صورت پیش‌فرض دسترسی اجرای `x` ندارند.*
* **حداکثر دسترسی پایه برای دایرکتوری‌ها:** `777` (`rwxrwxrwx`)

### 🧮 فرمول محاسبه umask:
مقدار `umask` از حداکثر دسترسی پایه **کم (تفریق)** می‌شود:

$$\text{مجوز نهایی فایل} = 666 - \text{umask}$$
$$\text{مجوز نهایی دایرکتوری} = 777 - \text{umask}$$

---

### 🔹 مثال‌های کاربردی:

#### مثال ۱: umask استاندارد دبیان (`0022` یا `022`)
* **برای دایرکتوری:** $777 - 022 = 755$ (`rwxr-xr-x`)
* **برای فایل:** $666 - 022 = 644$ (`rw-r--r--`)
> *نتیجه:* فقط مالک فایل حق ویرایش دارد، بقیه فقط حق خواندن دارند.

#### مثال ۲: umask سخت‌گیرانه پروژه‌های امنیتی (`0077` یا `077`)
* **برای دایرکتوری:** $777 - 077 = 700$ (`rwx------`)
* **برای فایل:** $666 - 077 = 600$ (`rw-------`)
> *نتیجه:* هیچ‌کس به جز خودِ مالک (نه گروه و نه افراد دیگر) هیچ دسترسی به فایل نخواهند داشت.

---

### 🔹 دستورات و نحوه تغییر umask:

**مشاهده umask فعلی:**
```bash
umask
# خروجی عددی، مثلاً: 0022

# مشاهده به‌صورت نمادین (Symbolic):
umask -S
# خروجی: u=rwx,g=rx,o=rx
```

### تغییر موقت umask (فقط برای جلسه کاری فعلی):

``umask 027``

(با این umask، فایل‌های جدید با دسترسی ``640`` و دایرکتوری‌ها با دسترسی ``750``ساخته می‌شوند).

تغییر دائمی umask برای یک کاربر خاص:

کافیست دستور فوق را به انتهای فایل ``~/.bashrc`` یا ``~/.profile`` کاربر اضافه کنید:

```
echo "umask 027" >> ~/.bashrc
source ~/.bashrc
```

تغییر دائمی umask برای تمام کاربران سیستم:

فایل ``/etc/profile`` یا فایل تنظیمات مربوطه در ``/etc/pam.d/common-session`` را ویرایش کرده و مقدار ``umask`` را تغییر دهید.

### 2️⃣ سطوح دسترسی ویژه (Special Permissions)

گاهی اوقات دسترسی‌های ساده ``rwx`` پاسخگوی نیازهای امنیتی نیستند. لینوکس ۳ مجوز ویژه ارائه می‌دهد:

```
─── SUID (4000)  -> روی فایل اجرا می‌شود (اجرا با دسترسی مالک)
 ─── SGID (2000)  -> روی دایرکتوری/فایل اجرا می‌شود (ارث‌بری گروه)
 ─── Sticky Bit (1000) -> روی دایرکتوری اجرا می‌شود (جلوگیری از حذف فایل‌های دیگران)
```

1. SUID (Set User ID) — عدد 4

وقتی SUID روی یک فایل اجرایی تنظیم شود، هر کاربری که آن فایل را اجرا کند، فرآیند مربوطه با سطح دسترسی مالک فایل (نه اجرای‌کننده) اجرا خواهد شد.

#### مثال ۳: بررسی فایل ``/usr/bin/passwd``

کاربران عادی باید بتوانند پسورد خود را تغییر دهند؛ این کار نیازمند نوشتن در فایل حساس ``/etc/shadow`` است که فقط ``root`` به آن دسترسی دارد!

```
ls -l /usr/bin/passwd
# خروجی: -rwsr-xr-x 1 root root 68248 Jan 1 10:00 /usr/bin/passwd
```

حرف ``s`` به جای ``x`` در بخش مالک، نشان‌دهنده SUID است.

ست کردن SUID روی اسکریپت/فایل اختصاصی:

```
sudo chmod u+s /usr/local/bin/my_tool
# یا عددی:
sudo chmod 4755 /usr/local/bin/my_tool
```

### 2. SGID (Set Group ID) — عدد 2

* روی فایل: برنامه هنگام اجرا، دسترسی گروه مالک فایل را می‌گیرد.
* روی دایرکتوری (بسیار پرکاربرد): هر فایل یا ساب‌دایرکتوری جدیدی که درون این دایرکتوری ساخته شود، به‌طور خودکار گروه مالک دایرکتوری اصلی را به ارث می‌برد.

#### مثال ۴: راه‌اندازی دایرکتوری اشتراکی برای یک تیم

```
sudo mkdir /srv/dev_share
sudo chown :developers /srv/dev_share

# فعال‌سازی SGID روی دایرکتوری
sudo chmod g+s /srv/dev_share
# یا عددی:
sudo chmod 2775 /srv/dev_share
```

حالا اگر کاربر ``alice`` فایلی بسازد، گروه آن به‌جای ``alice`` به‌صورت خودکار ``developers`` خواهد شد.

### 3. Sticky Bit — عدد 1

این مجوز روی دایرکتوری‌ها ست می‌شود. در دایرکتوری‌هایی که Sticky Bit دارند، کاربران حتی اگر دسترسی نوشتن داشته باشند، **فقط و فقط می‌توانند فایل‌هایی که خودشان مالک آن هستند را پاک یا نام‌گذاری مجدد کنند.**

#### مثال ۵: بررسی دایرکتوری /tmp سیستم‌عامل

```
ls -ld /tmp
# خروجی: drwxrwxrwt 12 root root 4096 Sep 14 12:00 /tmp
```

حرف ``t`` در انتهای دسترسی نشان‌دهنده Sticky Bit است.

تنظیم Sticky Bit روی دایرکتوری دلخواه:

```
sudo chmod +t /srv/public_uploads
# یا عددی:
sudo chmod 1777 /srv/public_uploads
```

### 3️⃣ معرفی و کاربرد لینک‌های سخت (Hard Links)

برای فهم لینک‌ها باید بدانید در لینوکس فایل شامل دو بخش است:

1. داده‌های واقعی (Data Blocks)
2. اطلاعات متادیتا (Inode): شامل مالک، دسترسی‌ها، زمان ساخت و آدرس بلوک‌های داده روی دیسک.

### 🔗 ا Hard Link چیست؟

هارد لینک، یک نام یا ورودی جدید در دایرکتوری است که مستقیماً به همان Inode قبلی اشاره می‌کند. به زبان ساده‌تر: یک فایل واحد با دو یا چند اسم متفاوت!

```
[ Name: file1.txt ] ────┐
                        ├───▶ [ Inode #12345 ] ────▶ [ Data Blocks on Disk ]
[ Name: hardlink.txt ] ─┘
```

### 🔹 ویژگی‌های کلیدی Hard Link:

* تغییر در محتوای هارد لینک، محتوای فایل اصلی را تغییر می‌دهد (چون داده‌ها یکی هستند).
* پاک کردن فایل اصلی، باعث پاک شدن اطلاعات نمی‌شود! داده‌ها تا زمانی که آخرین هارد لینک پاک نشود روی دیسک باقی می‌مانند.
* محدودیت ۱: نمی‌توان برای دایرکتوری‌ها Hard Link ساخت.
* محدودیت ۲: نمی‌توان روی پارتیشن‌ها یا فایل‌سیستم‌های متفاوت (مثلا از ``/dev/sda1`` به ``/dev/sdb1``) Hard Link ایجاد کرد.

### 🔹 مثال‌های عملی کار با Hard Link:

#### مثال ۶: ساخت Hard Link با دستور ``ln``


```
# ساخت یک فایل نمونه
echo "Hello Debian" > original.txt

# ایجاد لینک سخت
ln original.txt hardlink1.txt

# بررسی Inode و تعداد لینک‌ها با ls -li
ls -li original.txt hardlink1.txt
```

خروجی نمونه:

```
1234567 -rw-r--r-- 2 arvin arvin 13 Sep 14 15:00 hardlink1.txt
1234567 -rw-r--r-- 2 arvin arvin 13 Sep 14 15:00 original.txt
```

توضیح خروجی:

* عدد ``1234567`` شماره Inode یکسان هر دو فایل است.
* عدد ``2`` بعد از دسترسی‌ها نشان‌دهنده Link Count (تعداد هارد لینک‌های متصل به این Inode) است.

### تست پاک کردن فایل اصلی:

```
rm original.txt
cat hardlink1.txt
# محتوا همچنان نمایش داده می‌شود!
```

### 4️⃣ معرفی لینک‌های نمادین (Symbolic Links) و مقایسه با Hard Link

### 🔗 Symbolic Link (Symlink / Soft Link) چیست؟

سافت لینک دقیقاً مانند Shortcut در ویندوز است. لینک نمادین یک فایل کاملاً مستقل با یک Inode جدید است که تنها محتوای درون آن، آدرس متنی (Path) فایل یا دایرکتوری مقصد است.

```
[ Name: symlink.txt ] ──▶ [ Inode #99999 ] ──▶ "path/to/original.txt"
                                                      │
                                                      ▼
                                              [ Inode #12345 ] ──▶ [ Data ]
```

### 🔹 ویژگی‌های کلیدی Symbolic Link:

* می‌توان برای دایرکتوری‌ها نیز Symlink ساخت.
* می‌توان بین پارتیشن‌ها و فایل‌سیستم‌های مختلف Symlink ایجاد کرد.
* اگر فایل اصلی پاک شود، Symlink آسیب می‌بیند (اصطلاحاً Broken Link یا Orphan Link می‌شود).

### 🔹 مثال‌های عملی کار با Symbolic Link:

### مثال ۷: ساخت Symlink برای فایل و دایرکتوری (``ln -s``)

```
# ساخت لینک نمادین برای یک فایل
ln -s /var/log/syslog ~/my_syslog_link

# ساخت لینک نمادین برای یک دایرکتوری پروژه
ln -s /var/www/html/my_project ~/my_project_link
```

### بررسی با ``ls -l``:

```
ls -l ~/my_syslog_link
```

خروجی نمونه:

```
lrwxrwxrwx 1 arvin arvin 15 Sep 14 15:10 my_syslog_link -> /var/log/syslog
```

حرف ``l`` در ابتدای مجوزها نشان‌دهنده Link بودن فایل است.

### 📊 جدول مقایسه جامع: Hard Link در برابر Symbolic Link

| ویژگی |  Hrad Link | symbolic link (soft link)
| :--- | :--- | :--- |
شماره Inode | با فایل اصلی یکسان است | یک Inode جدید و مجزا دارد |
| پشتیبانی از دایرکتوری | ❌ خیر (توسط کاربر عادی ممکن نیست) | بله |
| عبور از پارتیشن‌ها (Cross-filesystem) | ❌ خیر (فقط درون یک پارتیشن) | بله |
| تأثیر حذف فایل اصلی | داده‌ها سالم می‌مانند (تا حذف آخرین لینک) | لینک خراب می‌شود (Broken Link) |
| مصرف فضای دیسک | هیچی اضافه نمی‌شود (فقط یک ورودی متنی) |  مقدار بسیار کمی (در حد حجم متنی مسیر) |
| دستور ساخت | ``ln target link_name`` | ``ln -s target link_name`` | 

### 5️⃣ ارسال ایمیل محلی بین کاربران سیستم (Mail Transfer Agent - MTA)

در سیستم‌عامل‌های لینوکس و لایسنس‌های سروری، برنامه‌ها و سرویس‌ها (مانند Cron Jobs یا ابزارهای امنیتی) گزارش‌ها و هشدارهای خود را از طریق سیستم ایمیل داخلی (Local Mail System) برای کاربران ارسال می‌کنند.

برای این کار نیازی به اینترنت نیست؛ ترافیک ایمیل تماماً درون لایه سیستم‌عامل و از طریق پروتکل‌های داخلی عبور می‌کند.

### 🔹 ابزارهای مورد نیاز:

* ا MTA (Mail Transfer Agent): مسئول جابه‌جایی و تحویل ایمیل‌ها (مانند ``postfix`` یا ``exim4`` یا ``mailx``).
* ا Mail Client (MUA): ابزار خواندن ایمیل در ترمینال (مانند ``bsd-mailx`` یا ``mailutils`` یا ``mutt``).

### 🚀 راه اندازی و ارسال ایمیل محلی گام‌به‌گام

### گام ۱: نصب ابزار ``mailutils`` و Postfix (در توزیع‌های مبتنی بر دبیان)

```
sudo apt update

```

(هنگام نصب Postfix اگر منویی باز شد، گزینه Local Only را انتخاب کنید و نام دامنه محلی را همان ``localhost`` بگذارید).
