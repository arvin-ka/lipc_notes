## 1️⃣ مدیریت حساب‌های کاربری در لینوکس

در لینوکس هر فرد یا سرویس نرم‌افزاری دارای یک حساب کاربری (User Account) مجزا با یک **UID (User Identifier)** منحصر‌به‌فرد است:
* **`UID 0`**: متعلق به کاربر ارشد سیستم (`root`) است که دسترسی نامحدود دارد.
* **`UID 1 - 999`**: متعلق به کاربران سیستم‌عاملی و سرویس‌ها (System Users/Services) است (مانند `www-data`, `nobody`).
* **`UID 1000+`**: متعلق به کاربران معمولی (Regular Users) است.

---

### 🔹 دستورات اصلی مدیریت کاربران

#### ۱. ایجاد کاربر جدید (`useradd` و `adduser`)
در توزیع‌های مبتنی بر دبیان دو ابزار وجود دارد:
- `useradd`: ابزار کم‌سطح (Low-level) که نیازمند سوئیچ‌های متعدد است.
- `adduser`: ابزاری تعاملی و پرکاربردتر که دایرکتوری خانگی و پسورد را به‌صورت خودکار پیکربندی می‌کند.

**مثال ۱: ساخت کاربر معمولی با `useradd`**
```bash
# ساخت کاربر dev_user با دایرکتوری home، شل bash و توضیحات کامل
sudo useradd -m -s /bin/bash -c "Senior Developer" dev_user
```

* سوئیچ ``-m``: ایجاد دایرکتوری ``/home/dev_user``
* سوئیچ ``-s``: تعیین شل پیش‌فرض
* سوئیچ ``-c``: اضافه کردن توضیحات (Comment)

#### مثال ۲: تعویض/تنظیم رمز عبور کاربر

``sudo passwd dev_user``

2. ویرایش مشخصات کاربر (``usermod``)

از دستور ``usermod`` برای تغییر ویژگی‌های یک کاربر موجود استفاده می‌شود.

#### مثال ۳: قفل کردن و باز کردن حساب کاربری

```
# قفل کردن حساب (کاربر امکان ورود نخواهد داشت)
sudo usermod -L dev_user

# باز کردن حساب کاربری
sudo usermod -U dev_user
```

#### مثال ۴: تغییر تاریخ انقضای حساب کاربری

```
# تنظیم تاریخ انقضا تا انتهای سال ۲۰۲۶
sudo usermod -e 2026-12-31 dev_user
```

#### مثال ۵: تغییر شل اصلی کاربر

```
sudo usermod -s /bin/zsh dev_user
```

### حذف کاربر (``userdel``)

#### مثال ۶: حذف کاربر به همراه دایرکتوری خانگی و فایل‌هایش

```
sudo userdel -r dev_user
```

سوئیچ ``-r``: دایرکتوری ``/home/dev_user`` و تمام محتویات آن را پاک می‌کند.

### 2️⃣ ایجاد و مدیریت گروه‌ها در لینوکس

گروه‌ها (Groups) برای دسته‌بندی کاربران و اعطای مجوزهای دسترسی یکسان به مجموعه‌ای از افراد استفاده می‌شوند. هر گروه دارای یک GID (Group Identifier) است.

### 🔹 انواع گروه:

1. Primary Group (گروه اصلی): همزمان با ساخت کاربر ایجاد می‌شود و معمولاً هم‌نام با نام کاربر است.
2. Secondary/Supplementary Group (گروه کمکی): گروه‌های اضافی که کاربر جهت دسترسی به منابع خاص به آن‌ها افزوده می‌شود (مثل ``sudo``, ``docker``, ``www-data``).

### 🔹 دستورات کاربردی گروه‌ها

### ساخت گروه جدید (``groupadd``)

#### مثال ۷: ساخت گروه توسعه‌دهندگان و گروه DevOps

```
sudo groupadd developers
sudo groupadd devops
```

۲. افزودن کاربر به گروه (``usermod`` / ``gpasswd``)

#### مثال ۸: افزودن کاربر به گروه کمکی (روش استاندارد)

```
# افزودن کاربر arvin به گروه developers بدون حذف گروه‌های قبلی (-aG)
sudo usermod -aG developers arvin
```

**⚠️ نکته بسیار مهم: همیشه از سوئیچ ``-``a (Append) 
همراه با ``-G`` استفاده کنید. اگر فقط از ``-G`` استفاده کنید، کاربر از تمام گروه‌های قبلی خود خارج می‌شود!**

#### مثال ۹: مدیریت اعضای گروه با ``gpasswd``

```
# افزودن کاربر به گروه
sudo gpasswd -a arvin devops

# حذف کاربر از گروه
sudo gpasswd -d arvin devops
```

3. ویرایش و حذف گروه (``groupmod`` و ``groupdel``)

#### مثال ۱۰: تغییر نام یک گروه موجود

 ``sudo groupmod -n dev_team developers``

#### مثال ۱۱: حذف یک گروه

``sudo groupdel dev_team``

### 3️⃣ روش‌های مشاهده اطلاعات کاربران و گروه‌ها

اطلاعات کاربران و گروه‌ها در فایل‌های متنی خاصی در مسیر ``/etc/`` ذخیره می‌شوند.

### 📂 فایل‌های کلیدی پیکربندی:

* ا ``/etc/passwd``: شامل اطلاعات کاربران (نام، UID، GID، دایرکتوری home و Shell).
* ا ``/etc/shadow``: شامل رمزهای عبور هش‌شده (Hashed Passwords) و تنظیمات انقضای رمز.
* ا ``/etc/group``: شامل اسامی گروه‌ها، GID و اعضای هر گروه.

### 🔹 دستورات مشاهده و بازرسی اطلاعات

1. مشاهده هویت کاربر جاری یا کاربر مشخص (``id`` / ``whoami``)

#### مثال ۱۲: بررسی تمام گروه‌ها و IDهای کاربر

``id arvin``

خروجی نمونه:

```
uid=1000(arvin) gid=1000(arvin) groups=1000(arvin),27(sudo),1001(developers)
```

2. بررسی کاربران متصل به سیستم (``last`` / ``w`` / ``who``)

#### مثال ۱۳: مشاهده کاربران فعال به همراه دستورات در حال اجرا

``w``

#### مثال ۱۴: مشاهده تاریخچه ورود کاربران به سیستم

``last -n 10``

3. جستجو و فیلتر فایل‌های سیستم با ``grep`` و ``cut``

 #### مثال ۱۵: مشاهده تمام کاربران عادی سیستم (UID بالای 1000)

``awk -F: '$3 >= 1000 {print $1, $3, $6}' /etc/passwd``
  
#### مثال ۱۶: مشاهده لیست اعضای یک گروه خاص

``grep "^developers:" /etc/group``

#### 4️⃣ مدیریت سطوح دسترسی کاربرها و گروه به فایل‌ها و دایرکتوری‌ها

در لینوکس، هر فایل و دایرکتوری شامل ۳ سطح دسترسی برای ۳ دسته از افراد است:

```
┌─── Owner (مالک فایل)
    │    ┌─── Group (اعضای گروه مالک)
    │    │    ┌─── Others (سایر کاربران سیستم)
    ▼    ▼    ▼
   rwx  r-x  r--
```

### 🔹 جدول کارکرد مجوزها:

| مجوز | علامت | مقدار عددی (Octal) | معنا روی فایل | معنا روی دایرکتوری |
| :--- | :--- | :--- | :--- | :--- |
| Read | ``r`` | 4 | خواندن محتوای فایل | مشاهده لیست فایل‌های داخل دایرکتوری (``ls``) |
|Write | ``w`` | 2 | 2	تغییر و ویرایش محتوای فایل | ساخت، حذف و تغییر نام فایل‌ها در دایرکتوری |
|Execute | ``x`` | 1 | 1	اجرای فایل (به عنوان اسکریپت یا برنامه) | ورود به دایرکتوری با دستور ``cd`` |

### 🔹 روش‌های تغییر مجوزها با دستور ``chmod``

روش اول: نمادین (Symbolic Mode)

در این روش از حروف زیر استفاده می‌شود:

* کاربران: ``u`` (User/Owner)، ``g`` (Group)، ``o`` (Others)، ``a`` (All)

* عملگرها: ``+`` (افزودن دسترسی)، ``-`` (حذف دسترسی)، ``=`` (تنظیم دقیق)
* مجوزها: ``r`` (Read), ``w`` (Write), ``x`` (Execute)

#### مثال ۱۷: اعطای دسترسی اجرا به مالک فایل

``chmod u+x script.sh``

#### مثال ۱۸: حذف دسترسی نوشتن برای گروه و سایرین

``chmod go-w document.txt``

#### مثال ۱۹: تنظیم دسترسی کامل برای مالک و عدم دسترسی به سایرین

``chmod u=rwx,g=r,o= private.key``

### روش دوم: عددی (Octal Mode)

در این روش مجموع اعداد هر بخش محاسبه می‌شود:

* ``7`` = ``4 + 2 + 1`` (``rwx``)
* ``6`` = ``4 + 2`` (``rw-``)
* ``5`` = ``4 + 1`` (``r-x``)
* ``4`` = ``4`` (``r--``)
  * ``0`` = هیچ دسترسی (``---``)
 
#### مثال ۲۰: دسترسی مرسوم برای پروژه‌های وب (فایل‌ها: 644، دایرکتوری‌ها: 755)

```
# فایل: مالک rw، گروه r، دیگران r
chmod 644 index.html

# دایرکتوری: مالک rwx، گروه r-x، دیگران r-x
chmod 755 /var/www/html
```

#### مثال ۲۱: اعمال مجوز به‌صورت بازگشتی (Recursive) روی تمام زیردایرکتوری‌ها

``chmod -R 750 /opt/project_files``
