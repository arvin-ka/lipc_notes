# 🌐 LPIC-1 Study Guide: Network Troubleshooting, Sockets & Diagnostic Tools (Objective 109.4)

این داکیومنت پوشش‌دهنده کامل **ماژول 109.4 از آزمون LPIC-1** است که روی ابزارها و دستورات پیشرفته عیب‌یابی شبکه، تحلیل اتصالات فعال، بررسی سوکت‌های لایه انتقال (TCP/UDP)، تست اتصالات لایه کاربرد و تشخیص مشکلات لایه‌های مختلف شبکه تمرکز دارد.

---

## 🛠️ 1. بازرسی اتصالات فعال و پورت‌ها (`ss` و `netstat`)

یکی از مهم‌ترین وظایف مدیر سیستم لینوکس، بررسی پورت‌های در حال گوش‌به‌زنگ (Listening) و اتصالات برقرار شده با پروسه‌های مختلف است.

### 🔹 ابزار سنتی `netstat` در برابر ابزار مدرن `ss`

ابزار `netstat` بخشی از پکیج قدیمی `net-tools` است، در حالی که `ss` (Socket Statistics) از پکیج `iproute2` بوده و سرعت بسیار بالاتری در استخراج اطلاعات از کرنل دارد.

| سوئیچ | عملکرد |
| :--- | :--- |
| **`-t`** | نمایش سوکت‌های **TCP** |
| **`-u`** | نمایش سوکت‌های **UDP** |
| **`-l`** | نمایش پورت‌های در حال گوش‌به‌زنگ (**Listening**) |
| **`-n`** | عدم ترجمه IP/Port به نام (نمایش به صورت **عددی**) |
| **`-p`** | نمایش **Process ID (PID)** و نام برنامه‌ای که پورت را باز کرده است (نیازمند `sudo`) |
| **`-a`** | نمایش **همه** سوکت‌ها (چه Listening چه Established) |

### 📌 دستورات پرکاربرد آزمون LPIC-1:

```bash
# مشاهده تمام پورت‌های TCP و UDP در حال گوش به زنگ همراه با شماره PID برنامه
sudo ss -tulnp

# دستور معادل با ابزار قدیمی netstat
sudo netstat -tulnp

# مشاهده اتصالات فعال TCP برقرار شده (Established)
ss -atn state established
```

### 🔍 2. ابزارهای استعلام و عیب‌یابی DNS

در لینوکس برای بررسی صحت پاسخ‌دهی سرورهای DNS و تحلیل رکوردهای نام دامنه از سه ابزار اصلی استفاده می‌شود:

### ا 1️⃣ ``dig`` (Domain Information Groper)

ابزار استاندارد و قدرتمند لینوکس برای استعلام دقیق DNS:

```
# دریافت تمام رکوردهای پایه یک دامنه
dig example.com

# دریافت فقط آدرس IP (خروجی تمیز برای اسکریپت‌نویسی)
dig example.com +short

# استعلام یک نوع رکورد خاص (مثل MX یا NS یا TXT)
dig example.com MX
dig example.com TXT

# استعلام مستقیم از یک DNS Server خاص (مثلاً 1.1.1.1)
dig @1.1.1.1 example.com
```

### ا 2️⃣ host

ابزار ساده و سریع برای پرس‌وجوهای ابتدایی و Reverse Lookup:

```
# تبدیل Name به IP
host example.com

# تبدیل IP به Name (Reverse DNS Lookup)
host 93.184.216.34
```

### ا 3️⃣ ``nslookup``

ابزار قدیمی‌تر با قابلیت کارکرد در حالت تعاملی (Interactive Mode).

### 🔌 3. تست اتصالات لایه کاربرد و پورت‌ها (``nc`` / ``netcat``)

ابزار Netcat (``nc``) برای تست باز بودن پورت‌های خاص روی سرورهای مقصد در لایه‌های TCP/UDP استفاده می‌شود.

### 📌 سناریوهای کاربردی ``nc``:

```
# ۱. بررسی باز بودن یک پورت خاص روی سرور مقصد (Port Scanning تک پورت)
nc -zv 192.168.1.100 22

# ۲. بررسی باز بودن یک رنج پورت
nc -zv 192.168.1.100 20-80

# ۳. تست ارسال داده رو یک پورت UDP
nc -zuv 192.168.1.100 53
```

* ``-z``: حالت Zero-I/O (فقط اتصال را بررسی می‌کند و داده‌ای ارسال نمی‌کند).
* ``-v``: خروجی با جزئیات کامل (Verbose).
* ``-u``: استفاده از پروتکل UDP به جای TCP.

### 📊 4. تحلیل مسیر و بازرسی بسته‌ها (Traceroute & ICMP)

برای پیدا کردن نقطه قطع ارتباط در شبکه از ابزارهای لایه ۳ استفاده می‌شود:

### 🔹 ``ping``

ارسال بسته‌های ICMP Echo Request جهت تست پایداری ارتباط:

```
# ارسال تعداد مشخص بسته
ping -c 4 8.8.8.8
```

### 🔹 ``traceroute`` / ``tracepath``

مشاهده تمام روترها و گام‌هایی (Hops) که بسته طی می‌کند تا به مقصد برسد:

```
traceroute google.com
# ابزار tracepath نیاز به دسترسی root ندارد:
tracepath google.com
```

### 🔄 5. فرآیند خطایابی سیستماتیک شبکه (Troubleshooting Checklist)

بر اساس اصول کتاب LPIC-1، عیب‌یابی شبکه باید به ترتیب از لایه‌های پایین به بالا صورت گیرد:

1. کارت شبکه (Link): ``ip link show`` (آیا کارت شبکه UP است؟)
2. آدرس‌دهی (IP/Subnet): ``ip addr show`` (آیا IP درست اختصاص یافته است؟)
3. جدول مسیریابی (Routing/Gateway): ``ip route show`` (آیا Default Gateway ست شده است؟)
4. تست Gateway: ``ping <Gateway_IP``> (آیا روتر محلی پاسخ می‌دهد؟)
5. ارتباط خارجی: ``ping 8.8.8.8`` (آیا دسترسی به اینترنت برقرار است؟)
6. سرویس نام‌گذاری (DNS): ``dig example.com`` یا ``host example.com`` (آیا DNS کار می‌کند؟)
7. فایل‌های محلی: بررسی ``/etc/resolv.conf`` و ``/etc/hosts`` و ``/etc/nsswitch.conf``.
8. پورت و سرویس: ``ss -tulnp`` روی سرور و ``nc -zv <IP> <Port>`` از سمت کلاینت.
