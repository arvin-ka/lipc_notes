# راهنمای جامع و کاربردی پیکربندی، مدیریت و ارتقای امنیت دسترسی ریموت با SSH در لینوکس

## مقدمه: SSH چیست و چرا استفاده می‌شود؟

پروتکل **SSH (Secure Shell)** یک پروتکل شبکه‌ای امن و رمزنگاری‌شده است که به کاربران و مدیران سیستم اجازه می‌دهد از راه دور (Remote) به یک سرور لینوکسی متصل شوند، دستورات اجرا کنند، فایل‌ها را منتقل نمایند و سرویس‌های مختلف را مدیریت کنند.

در گذشته از پروتکل‌هایی مانند **Telnet** یا **RLOGIN** برای دسترسی ریموت استفاده می‌شد. مشکلی که این پروتکل‌ها داشتند این بود که تمامی اطلاعات (از جمله نام کاربری و رمز عبور) به صورت متن ساده (Plaintext) در شبکه منتقل می‌شد و هر فردی در مسیر شبکه می‌توانست با ابزارهای شنود (Packet Sniffer) آن‌ها را سرقت کند.

ا **SSH** این مشکل را حل کرد:
* ا **Encrypting Data:** تمامی ترافیک عبوری (شامل کلمات عبور و دستورات) رمزنگاری می‌شود.
* ا **Authentication:** هویت کلاینت و سرور به دقت احراز می‌شود تا حمله «مرد میانجی» (Man-in-the-Middle) خنثی شود.
* ا **Data Integrity:** سلامت داده‌های انتقالی بررسی می‌شود تا مشخص شود در طول مسیر دستکاری نشده‌اند.

## ۱. ساختار معماری SSH و نحوه کارکرد آن

ارتباط SSH بر اساس معماری **Client-Server** عمل می‌کند:
* ا **SSH Server (Daemon):** سرویسی است که روی سرور لینوکس اجرا می‌شود (معمولاً در لینوکس ابزار `openssh-server`) و منتظر درخواست‌های اتصال روی پورت مشخص (پیش‌فرض **22**) می‌ماند.
* ا **SSH Client:** برنامه‌ای است که روی سیستم کاربر (کلاینت) اجرا می‌شود تا درخواست اتصال را به سرور ارسال کند (مانند دستور `ssh` در ترمینال یا ابزار `PuTTY`).

### مراحل برقراری دسترسی (Handshake):
1. **برقراری اتصال TCP:** کلاینت روی پورت ۲۲ به سرور متصل می‌شود.
2. **تبادل کلید و رمزنگاری (Key Exchange):** کلاینت و سرور الگوریتم‌های رمزنگاری مشترک را توافق کرده و یک کلید متقارن یک‌بارمصرف (Symmetric Key) برای الگوریتم session رمزنگاری می‌سازند.
3. **تأیید هویت سرور (Host Key Verification):** کلاینت اثرانگشت (Fingerprint) کلید سرور را بررسی می‌کند.
4. **احراز هویت کاربر (User Authentication):** کاربر با استفاده از پسورد یا کلید اختصاصی (Public/Private Key) احراز هویت می‌شود.

## ۲. نصب و راه‌اندازی اولیه OpenSSH روی لینوکس

برای اینکه سرور لینوکس آماده پذیرش اتصالات باشد، باید پکیج سرور SSH روی آن نصب و سرویس آن فعال باشد.

### نصب OpenSSH Server

* **در توزیع‌های مبتنی بر اوبونتو و دبیان (Ubuntu / Debian):**
```bash
sudo apt update
sudo apt install openssh-server -y
```

* در توزیع‌های مبتنی بر ردت و کلاودلینوکس (RHEL / CentOS / Rocky Linux / AlmaLinux):

``sudo dnf install openssh-server -y``

* در توزیع‌های مبتنی بر آرچ (Arch Linux):

``sudo pacman -S openssh``

### مدیریت سرویس OpenSSH با systemctl

پس از نصب، باید سرویس SSH را فعال و روشن کنید:

* شروع به کار سرویس:

```
sudo systemctl start ssh    # در دبیان/اوبونتو
# یا
sudo systemctl start sshd   # در ردت/سنت‌او‌اس
```

* فعال‌سازی سرویس در زمان بوت سرور (Enable on boot):

```
sudo systemctl enable sshd
```

* بررسی وضعیت فعال بودن سرویس:

``sudo systemctl status sshd``

* ری‌استارت کردن سرویس (پس از اعمال تغییرات در فایل پیکربندی):

``sudo systemctl restart sshd``

## ۳. نحوه اتصال به سرور از طریق SSH

۳. نحوه اتصال به سرور از طریق SSH

``ssh [username]@[server_ip_address]``

مثال‌های کاربردی اتصال:

مثال ۱: اتصال ساده با نام کاربری و آدرس IP

``ssh arvin@192.168.1.100``

در این حالت، سیستم از شما رمز عبور کاربر ``arvin`` روی سرور را می‌پرسد.

مثال ۲: اتصال روی پورت غیر پیش‌فرض (مثلاً پورت 2222)

``ssh -p 2222 arvin@192.168.1.100``

مثال ۳: اتصال با استفاده از یک فایل کلید اختصاصی (Private Key)

``ssh -i ~/.ssh/my_custom_key arvin@192.168.1.100``

مثال ۴: اجرای مستقیم یک دستور بدون وارد شدن به شل سرور

``ssh arvin@192.168.1.100 "df -h"``

این دستور فضای دیسک سرور را خروجی داده و بلافاصله اتصال را قطع می‌کند.

## ۴. احراز هویت با استفاده از کلید SSH (SSH Key-Based Authentication)

استفاده از رمز عبور (Password) برای ورود به سرور نقاط ضعفی مانند خطرات حملات Brute-Force دارد. امن‌ترین روش اتصال به سرور، استفاده از جفت کلید SSH (Public/Private Key Pair) است.

این روش شامل دو کلید است:

1. ا Private Key (کلید خصوصی): روی سیستم شما (کلاینت) می‌ماند و هرگز نباید در اختیار کسی قرار گیرد.
2. ا Public Key (کلید عمومی): روی سرور لینوکس ذخیره می‌شود.

```
   +-------------------+                      +-------------------+
|   Client Machine  |                      |   Linux Server    |
|                   |                      |                   |
|  [ Private Key ]  | ====(Handshake)====> |  [ Public Key ]   |
|   (Keep Secret)   |                      | (~/.ssh/authorized_keys)
+-------------------+                      +-------------------+
```

### گام اول: ساخت جفت‌کلید روی سیستم کلاینت

بهترین و امن‌ترین الگوریتم فعلی Ed25519 است. اگر به دلایلی سیستم قدیمی باشد، از RSA با طول ۴۰۹۶ بیت استفاده می‌شود.

ایجاد کلید با الگوریتم Ed25519 (پیشنهادی):

``ssh-keygen -t ed25519 -C "arvin-laptop-key"``

ایجاد کلید با الگوریتم RSA 4096-bit:

``ssh-keygen -t rsa -b 4096 -C "arvin-desktop-rsa"``

توضیحات پارامترها:

* ا ``t-``: تعیین نوع الگوریتم (Type).
* ا ``b-``: تعیین طول کلید به بیت (Bits).
* ا ``C-``: افزودن یک کامنت یا برچسب برای شناسایی راحت‌تر کلید.

در هنگام اجرای دستور، از شما مسیر ذخیره‌سازی (پیش‌فرض ``ssh/id_ed25519./~``) و یک Passphrase (رمز عبور برای محافظت از خودِ کلید خصوصی) پرسیده می‌شود.

### گام دوم: انتقال کلید عمومی به سرور

برای اینکه سرور کلید شما را بشناسد، کلید عمومی باید در فایل ``ssh/authorized_keys./~`` کاربر مورد نظر در سرور قرار گیرد.

روش ۱: استفاده از ابزار اتوماتیک ``ssh-copy-id`` (روش آسان)

``ssh-copy-id -i ~/.ssh/id_ed25519.pub arvin@192.168.1.100``

در این مرحله پسورد کاربر از شما پرسیده می‌شود و کلید به طور خودکار منتقل می‌گردد.

### روش ۲: انتقال دستی کلید (در صورت عدم وجود ssh-copy-id)

1. ابتدا محتوای کلید عمومی را روی سیستم خود کپی کنید:

``cat ~/.ssh/id_ed25519.pub``

2. وارد سرور شوید و دستورات زیر را برای ساخت دایرکتوری و ذخیره کلید اجرا کنید:

```
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "محتوای_کپی_شده_کلید" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

## ۵. تنظیمات فایل اصلی پیکربندی SSH Server (``sshd_config``)

تمام تنظیمات سرور SSH در فایل زیر قرار دارد:

``/etc/ssh/sshd_config``

**هشدار: قبل از انجام هرگونه تغییر در این فایل، حتماً یک نسخه پشتیبان (Backup) تهیه کنید:**

``sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak``

جهت ویرایش فایل از یک ادیتور متنی مانند ``nano`` یا ``vim`` استفاده کنید:

``sudo nano /etc/ssh/sshd_config``

پارامترهای کلیدی و امنیتی در ``sshd_config``:

۱. تغییر پورت پیش‌فرض SSH

برای کاهش حملات اسکن اتوماتیک (Botnet Scans)، پورت را از ۲۲ به یک پورت غیرمعمول (مثلاً ۵۴۳۲۱) تغییر دهید:

``Port 54321``

### ۲. غیرفعال کردن ورود مستقیم کاربر Root

کاربر ``root`` نباید مستقیماً وارد سرور شود. کاربران باید ابتدا با یک کاربر معمولی وارد شده و در صورت نیاز با ``sudo`` دسترسی پیدا کنند:

``PermitRootLogin no``

### ۳. غیرفعال کردن ورود با پسورد (اجباری کردن کلید SSH)

پس از اینکه مطمئن شدید کلید SSH شما به درستی کار می‌کند، ورود با پسورد را غیرفعال کنید تا جلوی حملات Brute-Force گرفته شود:

```
PasswordAuthentication no
PubkeyAuthentication yes
```

### ۴. محدود کردن تعداد تلاش‌های ناموفق

تعداد تلاش‌های مجاز برای وارد کردن رمز عبور در یک اتصال را کاهش دهید:

``MaxAuthTries 3``

### ۵. محدود کردن کاربران یا گروه‌های مجاز برای اتصال

اگر می‌خواهید فقط کاربران خاصی اجازه اتصال ریموت داشته باشند:

``AllowUsers arvin admin_user``

یا بر اساس گروه:

``AllowGroups sshusers``

### ۶. تنظیم زمان Timeout برای قطعی اتصالات بی‌کار (Idle Sessions)

برای قطع خودکار نشست‌هایی که کاربر در آن هیچ فعالیتی ندارد:

```
ClientAliveInterval 300
ClientAliveCountMax 2
```

(در این تنظیم، سرور هر ۳۰۰ ثانیه (۵ دقیقه) یک سیگنال به کلاینت می‌فرستد. اگر تا ۲ بار پاسخی دریافت نکرد، اتصال را قطع می‌کند).

### ۷. غیرفعال کردن X11 Forwarding و Agent Forwarding (در صورت عدم نیاز)

```
X11Forwarding no
AllowAgentForwarding no
```

تأیید صحت تنظیمات و اعمال آن‌ها

پس از ذخیره فایل ``sshd_config``، حتماً قبل از ری‌استارت کردن سرویس، صحت دستورات (Syntax) را بررسی کنید:

``sudo sshd -t``

اگر خروجی هیچ خطایی نداد، می‌توانید سرویس را ری‌استارت کنید:

``sudo systemctl restart sshd``

نکته بسیار مهم: بعد از ری‌استارت کردن سرویس SSH، اتصال فعلی خود را ببندید! ابتدا یک ترمینال جدید باز کنید و اتصال با تنظیمات جدید را تست کنید. اگر مشکلی وجود داشت، در ترمینال قبلی که هنوز باز است می‌توانید آن را برطرف کنید.

## ۶. تنظیمات فایروال برای دسترسی SSH

اگر فایروال روی سرور فعال باشد، باید پورت SSH را در آن باز کنید؛ در غیر این صورت اتصال شما مسدود (Block) خواهد شد.

### ۱. تنظیم در فایروال UFW (مخصوص اوبونتو/دبیان)

* اگر از پورت پیش‌فرض (22) استفاده می‌کنید:

```
sudo ufw allow ssh
# یا
sudo ufw allow 22/tcp
```

* اگر پورت SSH را به ۵۴۳۲۱ تغییر داده‌اید:

``sudo ufw allow 54321/tcp``

* فعال‌سازی و بررسی وضعیت UFW:

```
sudo ufw enable
sudo ufw status
```

### ۲. تنظیم در فایروال FirewallD (مخصوص RHEL/CentOS/Rocky Linux)

* اگر از پورت پیش‌فرض استفاده می‌کنید:

```
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
```

* اگر پورت اختصاصی (مثلاً ۵۴۳۲۱) تعریف کرده‌اید:

```
sudo firewall-cmd --permanent --add-port=54321/tcp
sudo firewall-cmd --reload
```

## ۷. ساخت فایل کانفیگ کلاینت (``ssh/config./~``)

اگر با سرورهای متعدد کار می‌کنید، حفظ کردن آدرس‌های IP، پورت‌ها، نام‌های کاربری و مسیر کلیدها سخت خواهد بود. شما می‌توانید در سیستم کلاینت خود یک فایل کانفیگ بسازید.

فایل ``ssh/config./~``  را روی سیستم خود ایجاد یا ویرایش کنید:

``nano ~/.ssh/config``

نمونه نمونه فایل کانفیگ کلاینت:

```
# سرور اصلی پروژه
Host main-server
    HostName 192.168.1.100
    User arvin
    Port 54321
    IdentityFile ~/.ssh/id_ed25519

# سرور تست
Host staging
    HostName 10.0.0.50
    User devuser
    Port 22
    IdentityFile ~/.ssh/id_rsa_staging

# سرور با اتصال از طریق Bastion/Jump Host
Host internal-db
    HostName 172.16.0.5
    User dbadmin
    ProxyJump main-server
```

نحوه استفاده:

حالا به جای نوشتن دستورات طولانی، فقط کافیست اسم مستعار (Alias) را وارد کنید:

``ssh main-server``

سیستم به طور خودکار به ``192.168.1.100`` IP روی پورت ``54321`` با کاربر ``arvin`` و کلید مربوطه متصل می‌شود!

## ۸. انتقال فایل امن روی SSH: دستورات ``scp`` و ``rsync``

علاوه بر دسترسی ترمینالی، SSH بستری امن برای انتقال فایل‌ها فراهم می‌کند.

### ۱. دستور SCP (Secure Copy Protocol)

* کپی کردن یک فایل از سیستم کلاینت به سرور:

``scp -P 54321 local_file.txt arvin@192.168.1.100:/home/arvin/destination/``

* کپی کردن یک فایل از سرور به سیستم کلاینت:

``scp -P 54321 arvin@192.168.1.100:/home/arvin/remote_file.txt ~/Downloads/``

* کپی کردن یک پوشه (Directory) به همراه محتویات (دستور ``-r``):

``scp -P 54321 -r ./my_folder arvin@192.168.1.100:/home/arvin/``

### ۲. دستور Rsync (پیشرفته‌تر، سریع‌تر و قابلیت Sync)

ابزار ``rsync`` بسیار بهینه‌تر از ``scp`` است زیرا فقط تغییرات فایل‌ها را منتقل می‌کند و امکان ادامه انتقال در صورت قطعی شبکه را دارد.

* همگام‌سازی یک پوشه با سرور روی پورت غیرپیش‌فرض:

``rsync -avz -e "ssh -p 54321" ./project_files/ arvin@192.168.1.100:/var/www/html/``

توضیح پارامترها:

* ا (archive)``a-``: حفظ تمامی مجوزها (Permissions)، تاریخ‌ها و مالکیت فایل‌ها.
* ا (verbose)``v-``: نمایش جزئیات پیشرفت انتقال.
* ا (compress)``z-``: فشرده‌سازی داده‌ها در هنگام انتقال برای افزایش سرعت.
* ا ``e-`` تعیین دستور اتصال ریموت و پورت اختصاصی SSH.

## ۹. تکنیک‌های پیشرفته SSH

### ۱. تونل‌زنی و Port Forwarding

ا SSH به شما اجازه می‌دهد ترافیک شبکه‌ای خود را به صورت امن از طریق سرور هدایت کنید.

### الف) Local Port Forwarding

فرض کنید یک سرویس وب (مثلاً دشبورد پایگاه داده) روی سرور لینوکس اجرا شده که فقط روی ``localhost:8080`` سرور دسترسی دارد و از اینترنت قابل مشاهده نیست. شما می‌توانید آن را روی پورت سیستم خود مپ کنید:

``ssh -L 9000:localhost:8080 -p 54321 arvin@192.168.1.100``

حال اگر در مرورگر سیستم خود آدرس ``http://localhost:9000`` را باز کنید، سرویس روی سرور نمایش داده می‌شود.

### ب) Dynamic Port Forwarding (ایجاد SOCKS5 Proxy)

می‌توانید از سرور لینوکسی خود به عنوان یک پروکسی امن برای عبور ترافیک مرورگر استفاده کنید:

``ssh -D 1080 -q -C -N -p 54321 arvin@192.168.1.100``

پارامترها:

* ا ``1080 D-``: راه اندازی پروکسی SOCKS5 روی پورت ۱۰۸۰ سیستم کلاینت.
* ا ``f-`` / ``-N``: عدم اجرای دستور روی سرور و اجرا در پس‌زمینه.
* ا ``C-``: فشرده‌سازی داده‌ها.

### ۲. مدیریت نشست‌ها با Tmux یا Screen

هنگامی که از طریق SSH متصل هستید، در صورت قطعی اینترنت، دستور در حال اجرا متوقف می‌شود. برای جلوگیری از این مشکل، روی سرور از ابزار ``tmux`` یا ``screen`` استفاده کنید.

* نصب tmux روی سرور:

``sudo apt install tmux   # دبیان/اوبونتو``

* شروع یک نشست جدید:

``tmux new -s my_session``

* خارج شدن از نشست بدون قطع شدن برنامه‌ها (Detach):

کلیدهای ترکیبی ``Ctrl + B`` و سپس کلید ``D`` را فشار دهید.

* اتصال مجدد به نشست قبلی پس از اتصال مجدد SSH:

``tmux attach -t my_session``

## ۱۰. سخت‌سازی امنیتی پیشرفته (Hardening SSH)

برای رساندن امنیت سرور به بالاترین سطح ممکن، اقدامات زیر توصیه می‌شود:

### ۱. نصب و کانفیگ Fail2Ban

ابزار Fail2Ban لوگ‌های SSH را مانیتور می‌کند و در صورت مشاهده تعداد مشخصی تلاش ناموفق برای ورود، IP مهاجم را به طور خودکار در فایروال مسدود (Ban) می‌کند.

* نصب Fail2Ban:

```
sudo apt install fail2ban -y   # Ubuntu/Debian
sudo dnf install fail2ban -y   # RHEL/CentOS
```

* تنظیم فایل پیکربندی (``/etc/fail2ban/jail.local``):

```
[sshd]
enabled = true
port = 54321
logpath = %(sshd_log)s
maxretry = 3
findtime = 600
bantime = 3600
```

(در این کانفیگ، اگر از یک IP ظرف ۱۰ دقیقه (۶۰۰ ثانیه)، ۳ بار پسورد اشتباه وارد شود، آن IP به مدت ۱ ساعت (۳۶۰۰ ثانیه) مسدود می‌شود).

### ۲. فعال‌سازی احراز هویت دو مرحله‌ای (2FA / MFA)

برای افزودن یک لایه امنیتی دیگر (مانند کد Google Authenticator) علاوه بر کلید SSH:

1. نصب ماژول PAM مربوطه:

``sudo apt install libpam-google-authenticator -y``

2. اجرای پیکربندی برای کاربر:

``google-authenticator``

3. فعال‌سازی آن در ``/etc/pam.d/sshd`` با افزودن خط زیر:

``auth required pam_google_authenticator.so``

4. تغییر در ``sshd_config``:

```
KbdInteractiveAuthentication yes
UsePAM yes
```

## ۱۱. عیب‌یابی (Troubleshooting) خطاهای رایج SSH

| خطای مشاهده شده | علت احتمالی | روش حل مشکل |
| :--- | :--- | :--- |
| ``Connection refused`` | سرویس SSH روشن نیست یا پورت اشتباه وارد شده است. | اجرای ``systemctl status sshd`` و بررسی پورت تنظیم شده در ``sshd_config``.|
| ``Permission denied (publickey)`` | کلید SSH اشتباه است، مجوز فایل‌ها نادرست است یا ورود پسوردی مسدود شده. | بررسی فایل ``authorized_keys`` و تنظیم مجوزهای فایل با ``chmod 600`` و ``chmod 700``.|
|``Host key verification failed`` | کلید سرور تغییر کرده است (مثلاً سرور مجدداً نصب شده است). | حذف خط مربوط به IP سرور از فایل ``~/.ssh/known_hosts`` در سیستم کلاینت.|
| ``Connection timed out`` | فایروال سرور یا ISP پورت مربوطه را مسدود کرده است. | بررسی تنظیمات فایروال (``ufw`` یا ``firewalld``) و اطمینان از Open بودن پورت.|

### حالت اشکال‌زدایی (Verbose Mode)

اگر اتصالی برقرار نمی‌شود، با اضافه کردن پارامتر ``-v`` (یا ``-vvv`` برای جزئیات کامل) به دستور اتصال، علت دقیق مشکل را مشاهده کنید:

``ssh -vvv -p 54321 arvin@192.168.1.100``

* [x] غیرفعال کردن ورود با پسورد (``PasswordAuthentication no``).
* [x] تنظیم صحیح فایروال (``ufw`` / ``firewalld``).
* [x] نصب و فعال‌سازی ابزار ``Fail2Ban``.
* [x] تنظیم محدودیت کاربران مجاز (``AllowUsers``).
* [x] بررسی صحیح بودن مجوز دایرکتوری‌ها (700 برای ``.ssh`` و ``600`` برای ``authorized_keys``).
