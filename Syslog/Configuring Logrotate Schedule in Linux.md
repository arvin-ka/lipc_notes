# 🔄 راهنمایی جامع و کاربردی: مدیریت، چرخش و فشرده‌سازی لاگ‌ها با سرویس Logrotate در لینوکس

در سیستم‌عامل‌های خانواده لینوکس، سرویس‌ها و برنامه‌های کاربردی به‌صورت مداوم رویدادها را در قالب فایل‌های لاگ (Log Files) ثبت می‌کنند. اگر این فایل‌ها کنترل و بازبینی نشوند، پس از مدتی حجم بسیار زیادی از فضای دیسک را اشغال کرده و عملکرد کل سیستم را مختل می‌سازند.

ابزار Logrotate برای حل همین چالش طراحی شده است؛ یک ابزار استاندارد، حیاتی و پرکاربرد که فرآیند چرخش (Rotation)، فشرده‌سازی (Compression)، پاک‌سازی لاگ‌های قدیمی و ارسال گزارش‌ها را به‌صورت کاملاً خودکار و هوشمند مدیریت می‌کند. در این داکیومنت به بررسی عمیق مفاهیم، ساختار فایل‌های کانفیگ، پارامترهای کلیدی و سناریوهای واقعی پرداخته شده است.

## ۱. ا Logrotate چیست و چگونه کار می‌کند؟

ابزار logrotate خود به‌صورت یک دیمون (Daemon) پیوسته و در حال اجرا نیست، بلکه معمولاً توسط سیستم زمان‌بندی Cron (به‌طور روزانه via ``/etc/cron.daily/logrotate`` یا Cron Timer در Systemd) فراخوانی و اجرا می‌شود.

فرآیند چرخش لاگ (Log Rotation) چیست؟

وقتی یک فایل لاگ چرخیده می‌شود:

1. فایل اصلی لاگ (مثلاً ``app.log``) تغییر نام داده می‌شود (مثلاً به ``app.log.1``).
2. یک فایل لاگ جدید و خالی با همان نام اولیه (``app.log``) ایجاد می‌شود تا برنامه‌ها بتوانند بدون وقفه لاگ‌های جدید را در آن بنویسند.
3. لاگ‌های قدیمی‌تر یک مرحله به عقب منتقل می‌شوند (``app.log.1`` تبدیل به ``app.log.2`` می‌شود).
4. لاگ‌هایی که از تعداد نگهداری مجاز (Retention Limit) فراتر بروند، به‌صورت خودکار حذف می‌شوند.

## ۲. ساختار پیکربندی Logrotate

تنظیمات Logrotate در دو محل اصلی قرار دارند:

1. فایل اصلی پیکربندی: ``/etc/logrotate.conf``

* شامل تنظیمات سراسری (Global Settings) برای تمامی لاگ‌ها است.

2. دایرکتوری پیکربندی‌های اختصاصی: ``/etc/logrotate.d/``

* سرویس‌های مختلف (مانند Nginx, Apache, RSYSLOG, MySQL) فایل‌های تنظیمات اختصاصی خود را در این مسیر قرار می‌دهند.

**نکته: تنظیمات موجود در /etc/logrotate.d/ بر تنظیمات سراسری **/etc/logrotate.conf** اولویت دارند و آن‌ها را بازنویسی (Override) می‌کنند.**

## ۳. بررسی گزینه‌ها و پارامترهای مهم پیکربندی

در این بخش تمام پارامترهای کلیدی و پرکاربرد ``logrotate`` همراه با جزئیات بررسی می‌شوند:

### الف) زمان‌بندی و شرط چرخش (Rotation Conditions)

* ا ``daily``: چرخش روزانه فایل لاگ.
* ا ``weekly``: چرخش هفتگی (در اولین روز هفته).
* ا ``monthly``: چرخش ماهانه (در اولین روز ماه).
* ا ``yearly``: چرخش سالانه.
* ا ``size <number>[k|M|G]``: چرخش زمانی اتفاق می‌افتد که حجم فایل لاگ از مقدار مشخص‌شده فراتر برود (مثلاً ``size 100M`` یا ``size 10k``).
* ا ``minsize <size>``: چرخش براساس زمان انجام می‌شود، اما **تنها در صورتی** که حجم فایل لاگ از این مقدار بیشتر باشد.
* ا ``maxsize <size>``: چرخش براساس زمان انجام می‌شود، اما اگر قبل از رسیدن به زمان مقرر حجم فایل از این حد بگذرد، زودتر چرخیده خواهد شد.

### ب) تعداد و طول عمر نگهداری (Retention)

* ا ``rotate <number>``: تعداد نسخه‌های قدیمی نگه داشته شده قبل از حذف. (مثلاً ``rotate 4`` یعنی فقط ۴ نسخه قدیمی صیانت شده و ۵می حذف می‌شود).
* ا ``maxage <days>``: حذف فایل‌های لاگ چرخیده شده پس از گذشت تعداد روز مشخص.

### ج) فشرده‌سازی (Compression)

* ا ``compress``: فشرده‌سازی لاگ‌های قدیمی با پسوند پیش‌فرض .gz (با استفاده از Gzip). 
* ا ``nocompress``: عدم فشرده‌سازی لاگ‌های قدیمی.
* ا ``delaycompress``: تاخیر در فشرده‌سازی لاگ تا دور بعدی چرخش. (بسیار کاربردی برای برنامه‌هایی که پس از چرخش همچنان برای چند لحظه روی فایل قبلی می‌نویسند).
* ا ``compresscmd <command>``: تعیین ابزار فشرده‌سازی جایگزین (مثلاً ``bzip2`` یا ``xz``).

### د) رفتار با فایل‌ها و دایرکتوری‌ها

* ا ``missingok``: اگر فایل لاگ وجود نداشت، خطایی صادر نشود و فرآیند ادامه یابد.
* ا ``nomissingok``: در صورت نبودن فایل لاگ، خطا صادر شود (حالت پیش‌فرض). 
* ا ``notifempty``: اگر فایل لاگ خالی باشد (``0 bytes``)، چرخیده نشود.
* ا ``copytruncate``: به جای تغییر نام فایل لاگ اصلی، محتوای آن کپی شده و سپس فایل اصلی خالی (Truncate) می‌شود. (مناسب برای برنامه‌هایی که نمی‌توانند فایل لاگ جدید را باز کنند).
* ا ``create <mode> <owner> <group>``: ساخت فایل لاگ جدید با دسترسی‌ها، مالک و گروه مشخص (مثلاً ``create 0640 root adm``).
* ا ``olddir <directory>``: انتقال لاگ‌های قدیمی و چرخیده شده به یک دایرکتوری مجزا.
* ا ``dateext``: استفاده از تاریخ واقعی چرخش به جای شماره‌گذاری عددی در پسوند فایل (مثلاً ``app.log-20260919.gz``).
* ا ``dateformat -%Y-%m-%d``: تعیین فرمت تاریخ در صورت استفاده از ``dateext``.

### هـ) اسکریپت‌ها و دستورات اجرایی (Postrotate & Prerotate)

* ا ``prerotate ... endscript``: دستوراتی که قبل از انجام چرخش لاگ اجرا می‌شوند.
* ا ``postrotate ... endscript``: دستوراتی که بلافاصله بعد از چرخش لاگ اجرا می‌شوند (معمولاً برای ارسال سیگنال ``reload`` یا ``reopen`` به سرویس‌ها جهت بستن فایل لاگ قدیم و باز کردن فایل جدید).
* ا ``sharedscripts``: باعث می‌شود اسکریپت‌های ``prerotate`` و ``postrotate`` فقط یک‌بار برای کل ساختار بلوک اجرا شوند، نه به ازای هر فایل متطابق.

### ۴. مثال‌های عملی و سناریوهای کاربردی

### مثال ۱: ساختار فایل پیکربندی ساده برای یک برنامه سفارشی (``/etc/logrotate.d/myapp``)

فرض کنید برنامه‌ای دارید که لاگ‌های خود را در مسیر ``/var/log/myapp/app.log`` ذخیره می‌کند:

```
/var/log/myapp/app.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 0644 myuser mygroup
}
```

توضیح عملکرد:

* ا هر روز لاگ بررسی می‌شود (``daily``).
* ا حداکثر ۷ نسخه نگه داشته می‌شود (``rotate 7``).
* ا لاگ‌ها فشرده می‌شوند (``compress``)، اما اولین نسخه چرخیده‌شده فشرده نمی‌شود (``delaycompress``).
* ا اگر فایل وجود نداشت خطایی داده نمی‌شود (``missingok``).
* ا اگر فایل خالی بود، چرخیده نمی‌شود (``notifempty``).
* ا فایل جدید با دسترسی ``0644`` و مالکان ``myuser:mygroup`` ساخته می‌شود.

### مثال ۲: سناریوی حجمی (Size-based) برای یک وب‌سرور پرترافیک

  در سناریوهایی که ترافیک بالا است، انتظار برای سررسید روزانه یا هفتگی منطقی نیست و حجم دیسک را سریعاً پر می‌کند:

```
/var/log/nginx/*.log {
    size 100M
    rotate 10
    compress
    dateext
    dateformat -%Y-%m-%d-%s
    missingok
    sharedscripts
    postrotate
        if [ -f /var/run/nginx.pid ]; then
            kill -USR1 $(cat /var/run/nginx.pid)
        fi
    endscript
}
```
توضیح عملکرد:

* ا هر زمان حجم هرکدام از فایل‌های لاگ دایرکتوری Nginx به ``100MB`` برسد، چرخش انجام می‌شود.
* ا ۱۰ نسخه نگه داشته می‌شود.
* ا از پسوند تاریخ همراه با ثانیه (``%s``) استفاده می‌شود تا در صورت چند بار چرخش در یک روز نام فایل‌ها تکراری نشود.
* ا در بخش ``postrotate`` با ارسال سیگنال ``USR1`` به دیمون Nginx، از آن خواسته می‌شود تا فایل‌های لاگ را مجدداً باز کند (Reopen log files).

### مثال ۳: پیکربندی پیشرفته برای سرویس RSYSLOG

این سناریو لاگ‌های مختلف سیستم را که توسط RSYSLOG مدیریت می‌شوند بچرخاند:

```
/var/log/syslog
/var/log/auth.log
/var/log/cron.log {
    weekly
    rotate 4
    minsize 10M
    compress
    missingok
    notifempty
    sharedscripts
    postrotate
        /usr/lib/rsyslog/rsyslog-rotate
    endscript
}
```

توضیح عملکرد:

* چند فایل لاگ به‌صورت همزمان در یک بلوک تعریف شده‌اند.
* چرخش به‌صورت هفتگی است، به شرطی که حداقل حجم فایل ۱۰ مگابایت شده باشد (``minsize 10M``).
* پس از چرخش، اسکریپت ``rsyslog-rotate`` اجرا می‌شود تا سرویس RSYSLOG را مطلع کند.

## ۵. تست، عیب‌یابی و اجرای دستی Logrotate

برای اطمینان از صحت پیکربندی‌ها، نباید منتظر اجرای خودکار Cron ماند. ابزار ``logrotate`` سوئیچ‌های کاربردی برای تست ارائه می‌دهد:

### ۱. تست خشک (Dry Run) - بدون اعمال تغییرات واقعی

برای بررسی سلامت سنتکس و مشاهده اینکه Logrotate چه کارهایی انجام خواهد داد:

``logrotate --debug /etc/logrotate.d/myapp``

یا استفاده از حالت خلاصه:

``logrotate -d /etc/logrotate.conf``

### ۲. اجبار به چرخش (Force Rotate)

اگر می‌خواهید فارغ از شرایط زمانی و حجمی، چرخش همین حالا فوراً انجام شود:

``logrotate --force /etc/logrotate.d/myapp``

یا فرم کوتاه:

``logrotate -f /etc/logrotate.conf``

### ۳. بررسی وضعیت فایل‌ها (Status File)

ا Logrotate زمان آخرین چرخش هر فایل را در فایلی ثبت می‌کند. می‌توانید این وضعیت را مشاهده کنید:

``cat /var/lib/logrotate/status``

## ۶. خلاصه پارامترهای کلیدی (جدول مرجع)

| پارامتر | عملکرد و شرح |
| :--- | :--- |
|``daily / weekly / monthly`` | بازه زمانی اجرای چرخش. |
| ``size <size>`` | چرخش بر اساس حجم فایل (مثلاً ``50M``, ``1G``).|
| ``rotate <count>`` | تعداد نسخه‌های نگهداری‌شده. | 
| ``compress / delaycompress`` | فشرده‌سازی با Gzip / تاخیر در فشرده‌سازی تا دوره بعدی. |
| ``create <mode> <user> <group>`` | تعیین مشخصات فایل لاگ جدید پس از چرخش. | 
| ``copytruncate`` | کپی محتوا و خالی کردن فایل اصلی بدون قطع دسترسی برنامه. |
| ``missingok`` | عدم صادر کردن خطا در صورت عدم وجود فایل لاگ. |
| ``postrotate / endscript`` | اجرای اسکریپت یا دستورات پس از چرخش. |
